# 透明窗口文字渲染修复经验

> 2026-11-03 · MiHomeWin 桌面分区「文字发虚、彩边、多层颜色叠加」问题的完整排查记录。
> 适用场景：任何 Avalonia 透明/亚克力窗口上渲染小字号文字。

## 现象

白壁纸下分区卡片上的近白文字模糊不清，放大后文字周围有一圈**黑雾状彩边**，
红/蓝/青色噪点肉眼可见，观感像「多层颜色叠在一起」。

## 排查走过的弯路（按时间线）

| 尝试 | 结论 |
|---|---|
| 壁纸亮度检测，让底色浓度随壁纸变亮而加深 | 过度复杂化，且没治到根上；已撤 |
| 把遮罩浓度从 0.46 加到 0.66 | 对比度算错（用线性亮度直接套 WCAG），通透感全无；已撤 |
| 给 TextBlock 挂 DropShadowEffect 文字阴影（仿 DeskBox） | Avalonia 在 12.5px 小字上糊成 9px 灰雾，中等亮度底上整片发脏；已撤 |
| 反复调遮罩浓度 / tint | 均为治标，文字彩边依旧 |

**教训：先把「字糊」和「底透」拆成两个独立问题，分别测量，不要用同一个参数同时治。**

## 正确的排查方法：像素级测量

用 PIL 对截图做定量对比，而不是肉眼判断：

```python
# 文字边缘通道分离度：只取亮像素（笔画），统计 |R-B|
bright = [q for q in px if sum(q)/3 > 150]
sep = [abs(q[0]-q[2]) for q in bright]
```

实测结果（决定性证据）：

| 样本 | \|R−B\| 均值 | \|R−B\| 最大 |
|---|---|---|
| 本程序文字 | **20.8** | **197** |
| DeskBox 文字 | 1.9 | **2** |

DeskBox 的文字是**纯灰度**的；本程序的文字边缘存在严重红/蓝分离。

## 根因

本程序开启的是 **ClearType 亚像素抗锯齿**（Avalonia 默认）：利用 LCD 的 RGB
子像素排列提高小字锐度。但它只在**不透明背景**上有效——透明窗口上子像素采样
没有真实底色可依托，三个分量的采样偏差直接暴露成彩边，字形发虚。

参考软件 DeskBox（WinUI 3 / DirectWrite）在透明层上**自动退化为灰度抗锯齿**，
所以它「看不出任何特殊处理」文字却干净——不是它做了什么，而是它的渲染管线
不需要做。Avalonia 默认不退，需要手动指定。

## 修复

给**每个透明窗口**（`TransparencyLevelHint` 非 None 的）加一行：

```xml
RenderOptions.TextRenderingMode="Antialias"
```

强制灰度抗锯齿，与 DirectWrite 的透明层行为对齐。本仓库共 11 个透明窗口
（DesktopGroup / Appearance / GroupPick / Input / Menu / Picker / Rename /
SpeakerPick / Volume / DeviceControl / TrayMenu）。

### 为什么不能在 App.axaml 里一处配置（试过，编译不过）

```xml
<!-- AVLN2000: Unable to find TextRenderingModeProperty field on Avalonia.Media.RenderOptions -->
<Style Selector="Window">
    <Setter Property="RenderOptions.TextRenderingMode" Value="Antialias" />
</Style>
```

Avalonia 11.3 的 `RenderOptions.TextRenderingMode` 只有 CLR Get/Set 方法，
**没有 backing AvaloniaProperty**。写在元素标签上时 XAML 编译器直接生成 `Set…` 调用所以能过；
但 Style Setter 必须引用 `…Property` 静态字段，而该字段在 11.3.9 中不存在（文档里的
`TextOptions.*` 附加属性是更新版本的 API，11.3 没有）。

结论：**当前版本的最小正确形式 = 每个透明窗口一行**；属性沿视觉树从各 Window 向下继承，
窗口根上设一次即覆盖该窗口全部子元素。将来升级到带 `TextOptions` 的 Avalonia 版本后，
可合并成 App 级一处 Style。

不透明的窗口（如主窗口）**保持默认**，ClearType 在那里正常工作且更锐利。

## 期望变化与边界

- 切到灰度抗锯齿后，小字笔画比 ClearType **略细一点**——这是正常的，也正是
  DeskBox 的观感；彩边彻底消失。
- 灰度抗锯齿解决的是「彩边/发虚」，**不产生对比度**。透明窗口上文字要读得清，
  仍然需要底色遮罩提供足够对比（深色玻璃配白字是本项目的固定方向）。
- 文字阴影在本项目场景下**不要用**：Avalonia 的 DropShadowEffect 走 Skia，
  小字号上模糊半径会撑成灰雾；DeskBox 的文字阴影是 composition + GetAlphaMask
  （字形轮廓遮罩），Avalonia 没有等价物，别再尝试。

## 相关参数（本次一并定的口径）

- 底色浓度（外观面板「背景浓度」滑杆）= 卡片底色 alpha，范围 **0% ~ 72%**，
  默认 34%（`DesktopPalette.MinDensity/MaxDensity/DefaultDensity`）。
- DWM 磨砂染色 `TintOpacity = 0.10 × 浓度`，随浓度联动：0% 时纯磨砂无染色。
- 配置迁移走 `AppearanceVersion`（当前 = 2），只跑一次，不覆盖用户手调值。

## 一句话总结

**透明窗口上的小字彩边 = 亚像素抗锯齿失效，一行
`RenderOptions.TextRenderingMode="Antialias"` 修复；
文字对比度靠底色遮罩，两者是独立问题，分别测量、分别解决。**

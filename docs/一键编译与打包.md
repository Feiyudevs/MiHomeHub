# 一键编译与一键打包

MiHomeWin（MiHome / 米家桌面控制台）的构建发布入口。目标：改完代码一条命令跑起来，发版一条命令出安装包。

流程对齐 Zonex（`I:\AICode\Zonex\Zonex-avalonia\docs\一键编译与打包.md`）。

## 1. 两条命令

在 **cmd** 或 PowerShell 里（仓库根目录）：

```bat
build.cmd                 :: 编译 + 单文件发布 + 启动
build.cmd -NoRun          :: 只编译

package.cmd               :: 按当前版本打包（exe + 安装包 + SHA256）
package.cmd -Bump patch   :: 先升版本（1.0.0 -> 1.0.1）再打包
package.cmd -SkipInstaller:: 只出单文件 exe，不编安装包
```

> `.ps1` 不能在 cmd 里直接执行（双击/回车只会用记事本打开），所以根目录放 `build.cmd` / `package.cmd` 包装，
> 内部用 `powershell -NoProfile -ExecutionPolicy Bypass -File` 调脚本并透传参数。

等价 PowerShell 写法：

```powershell
.\scripts\build.ps1 [-NoRun]
.\scripts\release.ps1 [-Bump patch] [-SkipInstaller]
```

## 2. 产物结构

```
publish\
  sc-win-x64\                      # dotnet publish 原始产物，启动/回归的固定路径
    MiHome.exe                     # 自包含单文件（trim + 压缩）
  release\<版本>\
    MiHome.exe                     # 与 sc-win-x64 硬链接，不额外占磁盘
    MiHome-Setup-<版本>-win-x64.exe
    SHA256SUMS.txt
```

- 同一卷内用**硬链接**归档便携 exe；跨卷自动回退为复制。
- 安装包由 ISCC 直接编进版本目录（`OutputDir=..\publish\release\{#MyAppVersion}`）。
- `publish\` 已被 `.gitignore` 忽略，历史版本目录会一直保留。

## 3. 一键编译：`build.ps1` / `build.cmd`

1. `dotnet build -c Release`（csproj 的 Release 已带 `win-x64` RID）。
2. 校验 `bin\Release\net10.0\win-x64\MiHome.dll` 存在。
3. `-NoRun` 到此结束；否则调用 `publish-sc.ps1` 出单文件，再用 **explorer 托管启动**标准路径。

要点：

- **只运行 publish 产物**，不运行 `bin\Release`（裁剪行为与分发不一致，验证无效）。
- 发布前若标准路径的实例在跑，会按**完整路径精确匹配**强杀，否则文件被锁无法覆盖。
- 杀进程只允许「完整 exe 名 + `ExecutablePath` 落在本仓库 `publish\` 下」双重限定，禁止通配/前缀/窗口标题匹配。
- 本应用是**托盘常驻**：关闭窗口不退出；启动用 `explorer.exe` 托管，避免被当前命令会话回收。

## 4. 一键打包：`release.ps1` / `package.cmd`

1. **版本收口**（单一事实来源 = csproj 的 `<Version>`）：
   - csproj：`Version` = `x.y.z`，`AssemblyVersion` / `FileVersion` = `x.y.z.0`，`InformationalVersion` = `x.y.z`
   - `installer\MiHome.iss`：`#define MyAppVersion` 同步为同一版本
2. 停掉在跑的发布实例（精确路径）。
3. 调 `publish-sc.ps1`：自包含单文件 + 单文件压缩（**不开 PublishTrimmed**，见下）。
4. ISCC 编译安装包（直接落到 `publish\release\<版本>\`）。
5. 硬链接便携 exe，写 `SHA256SUMS.txt`，打印文件大小与版本目录。

### 版本参数

| 参数 | 行为 |
|---|---|
| 无 | 用 csproj 当前版本打包 |
| `-Bump patch\|minor\|major` | 按当前版本递增后再打包 |
| `-Version 1.2.0` | 指定版本（不能与 `-Bump` 同时用） |

**注意：版本号在编译前就已写入。** 如果打包中途失败（编译错误、ISCC 失败等），源码里的版本仍停在新版本；
重试时**不要**再带 `-Bump`，否则会连升两级。用无参数命令按当前版本重打即可。

### 安装包配置（`installer\MiHome.iss`）

- `AppVersion` / `VersionInfoVersion` 来自 `MyAppVersion`
- `SetupIconFile=..\Assets\logo.ico`：安装包图标 = 程序图标
- `UninstallDisplayIcon={app}\MiHome.exe`
- `PrivilegesRequired=admin`、`Compression=lzma2/max`、`CloseApplications=yes`
- `[Run]` 带 `postinstall skipifsilent`：安装完成后在「完成」页勾选才启动；静默安装不自动启动
- 打包只**编译**安装包，不会自动安装或运行它

## 5. 前置条件与故障处理

- **.NET SDK**：由根目录 `global.json` 固定（当前 10.0.301，rollForward latestPatch）。
- **Inno Setup 6**：`winget install --id JRSoftware.InnoSetup -e`。
  脚本依次查找 PATH、`%ProgramFiles%\Inno Setup 6\ISCC.exe`、`%ProgramFiles(x86)%\...`、`%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`；
  找不到时直接报错并给出安装命令（或用 `-SkipInstaller`）。
- **NuGet `path1 cannot be null`**：脚本已内置 `ProgramFiles` / `ProgramW6432` / `ProgramFiles(x86)` 环境变量兜底。
- **`-SkipInstaller` 与旧安装包**：脚本会删掉该版本目录里残留的 Setup，保证目录内容与 `SHA256SUMS.txt` 一致。
- **发布目录混入其它 exe**：脚本会告警（这些文件会被打进安装包），发布前确认 `publish\sc-win-x64` 干净。
- **为什么不开 PublishTrimmed**：XAML 已默认编译绑定，但仍有少量 ReflectionBinding + `System.Text.Json` 反射序列化；`TrimMode=link` 会裁掉登录（`auth.json`）、二维码、面板关闭等运行时依赖。详见 `TrimmerRoots.xml` 注释与 `AGENTS.md`。若将来要开裁剪，需先清完 ReflectionBinding、JSON 源生成并做完整回归。

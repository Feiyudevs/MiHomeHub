# 一键编译与一键打包

MiHomeWin（MiHome / 米家桌面控制台）的构建发布入口。目标：改完代码一条命令跑起来，发版一条命令出安装包。

构建脚本与发布流程集中在仓库根目录的 `build.cmd` / `package.cmd` 与 `scripts/`。

## 1. 两条命令

在 **cmd** 或 PowerShell 里（仓库根目录）：

```bat
build.cmd                 :: 编译 + 单文件发布 + 启动
build.cmd -NoRun          :: 只编译

package.cmd               :: 按当前版本打包（exe + 安装包 + SHA256）
package.cmd -Bump patch   :: 先升版本（1.0.0 -> 1.0.1）再打包
package.cmd -SkipInstaller:: 只出单文件 exe，不编安装包
```

> `.ps1` 不能在 cmd 里直接执行（双击/回车只会用记事本打开），所以根目录放 `build.cmd` / `package.cmd` 包装，
> 内部用 `powershell -NoProfile -ExecutionPolicy Bypass -File` 调脚本并透传参数。

等价 PowerShell 写法：

```powershell
.\scripts\build.ps1 [-NoRun]
.\scripts\release.ps1 [-Bump patch] [-SkipInstaller]
```

## 2. 产物结构

```
publish\
  sc-win-x64\                      # dotnet publish 原始产物，启动/回归的固定路径
    MiHome.exe                     # 自包含单文件（压缩）
  release\<版本>\
    MiHome.exe                     # 与 sc-win-x64 硬链接，不额外占磁盘
    MiHome-Setup-<版本>-win-x64.exe # 自研安装器（外壳 + 内嵌 payload）
    update.json                    # 应用内更新的清单（版本 / 文件名 / SHA256 / notes）
    SHA256SUMS.txt
```

- 同一卷内用**硬链接**归档便携 exe；跨卷自动回退为复制。
- 默认安装包是仓库自研安装器，不依赖 Inno Setup；`-Inno` 才回退到 ISCC。
- `publish\` 已被 `.gitignore` 忽略，历史版本目录会一直保留。

## 3. 一键编译：`build.ps1` / `build.cmd`

1. `dotnet build -c Release`（csproj 的 Release 已带 `win-x64` RID）。
2. 校验 `bin\Release\net10.0\win-x64\MiHome.dll` 存在。
3. `-NoRun` 到此结束；否则调用 `publish-sc.ps1` 出单文件，再用 **explorer 托管启动**标准路径。

要点：

- **只运行 publish 产物**，不运行 `bin\Release`（裁剪行为与分发不一致，验证无效）。
- 发布前若标准路径的实例在跑，会按**完整路径精确匹配**强杀，否则文件被锁无法覆盖。
- 杀进程只允许「完整 exe 名 + `ExecutablePath` 落在本仓库 `publish\` 下」双重限定，禁止通配/前缀/窗口标题匹配。
- 本应用是**托盘常驻**：关闭窗口不退出；启动用 `explorer.exe` 托管，避免被当前命令会话回收。

## 4. 一键打包：`release.ps1` / `package.cmd`

1. **版本收口**（单一事实来源 = csproj 的 `<Version>`）：
   - csproj：`Version` = `x.y.z`，`AssemblyVersion` / `FileVersion` = `x.y.z.0`，`InformationalVersion` = `x.y.z`
   - `installer\MiHome.Setup\MiHome.Setup.csproj` 与 `installer\MiHome.iss` 同步同一版本
2. 停掉在跑的发布实例（精确路径）。
3. 调 `publish-sc.ps1`：自包含单文件 + 单文件压缩（**不开 PublishTrimmed**，见下）。
4. 调 `package-setup.ps1`：主程序 + `LICENSE` / `NOTICE` / `THIRD-PARTY-NOTICES.md` → 唯一暂存目录 → payload zip → `dotnet publish` 外壳（payload 作为嵌入资源）→ 复制到版本目录。
5. 硬链接便携 exe，写 `SHA256SUMS.txt`，打印文件大小与版本目录。

### 版本参数

| 参数 | 行为 |
|---|---|
| 无 | 用 csproj 当前版本打包 |
| `-Bump patch\|minor\|major` | 按当前版本递增后再打包 |
| `-Version 1.2.0` | 指定版本（不能与 `-Bump` 同时用） |
| `-Inno` | 改用旧 Inno Setup 安装包（需 ISCC） |
| `-SkipInstaller` | 只发布 exe，不出安装包 |

**注意：版本号在编译前就已写入。** 如果打包中途失败（编译错误、安装器失败等），源码里的版本仍停在新版本；
重试时**不要**再带 `-Bump`，否则会连升两级。用无参数命令按当前版本重打即可。

### 自研安装器（默认）

- 外壳工程 `installer\MiHome.Setup`：WinExe、自包含单文件、裁剪、内嵌 `payload.zip`；主程序提供 Avalonia 安装/卸载界面。
- 默认装到 `%LOCALAPPDATA%\Programs\MiHome`（当前用户，**免管理员**）；程序在 `app\MiHome.exe`。
- 首次安装可点安装位置右侧「更改」选择本地目录；选到 `D:\Apps` 这类非空目录会自动落到 `D:\Apps\MiHome`。已安装后的升级/重装锁定原目录，不显示「更改」。
- 卸载登记写 `HKCU\...\Uninstall\MiHome`，`UninstallString` = `"...\app\MiHome.exe" --uninstall`。
- 安装界面提供「创建桌面快捷方式」；不提供开机自启开关，沿用应用自身 `app.json` 的 `AutoStart`（默认开）。
- 卸载默认保留 `%APPDATA%\Feiyu\MiHome`（布局、登录、设置），可勾选一并删除。
- 旧进程关闭：先 `CloseMainWindow`，再按安装目录精确筛选强杀，不做通配匹配。
- payload 暂存目录每次运行唯一（`publish\.setup\payload-<runId>` / `shell-<runId>`），避免并发与句柄竞态。
- `package-setup.ps1` / `preview-setup.ps1` 必须保持 **UTF-8 BOM**（Windows PowerShell 5.1 否则按 GBK 解码，吞掉换行导致解析失败）。

### 预览界面（不写入系统）

不实际安装，也能查看并点击完整安装/卸载流程：

```bat
preview.cmd                 :: 同时打开“安装”和“卸载”两个预览窗
preview.cmd install         :: 安装准备态
preview.cmd update          :: 更新态（0.9.0 -> 当前版本）
preview.cmd reinstall       :: 重装态
preview.cmd uninstall       :: 卸载确认态
preview.cmd error           :: 点击安装后的模拟失败态
```

预览仍会解压 payload 到 `%TEMP%` 以显示真实安装路径等状态，但**不会复制程序、不写注册表、不建快捷方式、不动用户数据**；完成后只关闭窗口。

### 旧 Inno 回退（`-Inno`）

- `installer\MiHome.iss`：`PrivilegesRequired=admin`、默认 `{autopf}\MiHome`、编译产物同样落到 `publish\release\<版本>\`。
- 仅用于兼容旧分发渠道；新版本优先用自研安装器。
- 需本机安装 Inno Setup 6（`winget install --id JRSoftware.InnoSetup -e`）。

## 5. 前置条件与故障处理

- **.NET SDK**：由根目录 `global.json` 固定（当前 10.0.301，rollForward latestPatch）。
- **默认安装器不需要 Inno Setup**；只有 `-Inno` 回退才需要 Inno Setup 6：`winget install --id JRSoftware.InnoSetup -e`。
  脚本依次查找 PATH、`%ProgramFiles%\Inno Setup 6\ISCC.exe`、`%ProgramFiles(x86)%\...`、`%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`；
  找不到时直接报错并给出安装命令（或用 `-SkipInstaller`）。
- **NuGet `path1 cannot be null`**：脚本已内置 `ProgramFiles` / `ProgramW6432` / `ProgramFiles(x86)` 环境变量兜底。
- **`-SkipInstaller` 与旧安装包**：脚本会删掉该版本目录里残留的 Setup，保证目录内容与 `SHA256SUMS.txt` 一致。
- **发布目录混入其它 exe**：脚本只收 `MiHome.exe`、许可文件和运行时附属文件；`*.old*` / `*.pre-old` / 旧安装包不会进 payload。
- **为什么不开 PublishTrimmed**：XAML 已默认编译绑定，但仍有少量 ReflectionBinding + `System.Text.Json` 反射序列化；`TrimMode=link` 会裁掉登录（`auth.json`）、二维码、面板关闭等运行时依赖。详见 `TrimmerRoots.xml` 注释与 `CONTRIBUTING.md`。若将来要开裁剪，需先清完 ReflectionBinding、JSON 源生成并做完整回归。

## 6. 远程打包：GitHub Actions

仓库自带一条完整打包流水线 `.github/workflows/build.yml`（workflow 名 `package`），复用同一套本地脚本：`publish-sc.ps1` + `package-setup.ps1`，与本地默认安装器一致。

- 触发：push 到 `main`、PR、手动 `workflow_dispatch`、push tag `v*`
- 步骤：setup .NET 10.0.301 → `publish-sc.ps1`（自包含单文件）→ `package-setup.ps1 -SkipMainPublish`（自研安装器 + `update.json`）→ 写 `SHA256SUMS.txt` → 上传 artifact `MiHome-<版本>-win-x64`（保留 30 天）
- push tag `v*` 时额外创建 GitHub Release，附 `MiHome.exe` / `MiHome-Setup-<版本>-win-x64.exe` / `SHA256SUMS.txt` / **`update.json`**（缺这个文件应用内自动更新会 404）
- 手动触发（`workflow_dispatch`）可选 `channel=test`：清单写 `channel=test`、30 天有效期，构建完把资产传到滚动 tag `test` 的 pre-release（正式通道看不到）

远程流水线**不升版本**：版本号只来自 csproj 的 `<Version>`。发版顺序：

1. 本地 `.\package.cmd -Bump patch` 出包并回归
2. 提交版本变更：`git commit -am "chore(release): v1.0.1"`
3. `git push origin main --tags`（或单独 `git tag v1.0.1 && git push origin v1.0.1`）→ Actions 远程重打包并挂 Release

## 7. 应用内自动更新

客户端更新走 **后台版本管理 + GitHub Releases 全量包**（后台为主、GitHub 兜底），不引入第三方更新框架：检查和下载由应用完成，替换/回滚仍交给自研安装器。

```
[关于页点检查/启动后自动查]（正式通道，且没有本地联调源）
  → GET {endpoint}/track/check-update   ← endpoint / appId 来自 MiHome.settings.json（本地可覆盖），不进代码
        ?app_id=<配置>&platform=Windows&app_version=<当前>&device_id=<本机UUID>
  → 后台没登记版本 / 网络失败 → 回落 GitHub：
       https://github.com/Feiyudevs/MiHomeHub/releases/latest/download/update.json
       → https://cdn.jsdelivr.net/gh/Feiyudevs/MiHomeHub@main/update.json
  → 版本比对（三段，复用 SetupFiles.CompareVersions）；should_update=false 且带 latest_version 视为灰度未覆盖
  → 下载：package_url（自建对象存储直链）→ GitHub Release 资产 → mirrors
  → 校验：能对上 GitHub 同名版本就用它的 SHA256 强校验；后台清单无哈希时只查大小（≥1MB）+ HTTPS
  → MiHome-Setup.exe --silent
      → 外壳解压 payload → MiHome.exe --setup --silent
      → SetupService 事务：app.new → 停旧进程 → app.old/app.previous 轮转 → 登记 → 拉起新版本
```

要点：

- **后台是可选项，配置写在仓库根的变量字段文件里**：`MiHome.settings.json`（随编译复制到 exe 同级，开源版本四项留空）：

  ```json
  {
    "backendEndpoint": "",
    "backendAppId": 0,
    "telemetryEndpoint": "",
    "telemetryAppId": 0
  }
  ```

  私有后台地址填 `MiHome.settings.local.json`（同在仓库根、已 `.gitignore`、存在才复制，只覆盖非空字段），或临时用环境变量 `MIHOME_BACKEND_BASE` / `MIHOME_BACKEND_APP_ID`。`backendEndpoint` + `backendAppId` 都有效才走后台；否则完全不碰后台，只用 GitHub。改完配置 `build.cmd` 一次让它复制到 `publish\sc-win-x64\`，或直接改那一份。
- **后台能做什么**：版本管理里建版本、填 `package_url`、设 `rolloutPercent` 即可灰度，`force` 打强制标记，`release_notes` 写更新说明；客户端把 `device_id` 带上去做分桶。
- **GitHub 兜底**：后台没配置、不可用、或该版本没配置安装包时回落 GitHub Release 清单；`update.json` 仍必须随 Release 上传（文件名带版本号，客户端靠清单知道下载哪个文件、校验值是多少），固定放 `releases/latest/download/update.json`，不走 `api.github.com`。
- **哈希来源**：后台 `check-update` 目前**不下发 SHA256**。客户端会在 GitHub 里找同版本借校验值，借不到就降级为“HTTPS + 大小合理性”校验；要强校验就把 `SHA256SUMS.txt` 里的值同步登记到后台。
- **镜像兜底**：`package-setup.ps1` 同时把 `update.json` 写到仓库根，jsDelivr 地址 `cdn.jsdelivr.net/gh/Feiyudevs/MiHomeHub@main/update.json` 作为第二源；要它生效需把仓库根的 `update.json` 一起提交。
- **校验**：清单 SHA256 与下载文件逐一比对，不匹配直接删除并报错，不执行任何安装动作。
- **静默安装**：`--silent` 跳过 Avalonia，全部在 `SetupService` 里跑；失败会弹最小错误框并保留旧版本（安装器事务自带回滚）。
- **检查频率**：启动后无感检查，24 小时内不重复请求；「关于 → 检查更新」可强制刷新。
- **安装包下载慢/失败**：不会影响正在运行的程序，只更新状态文案；清单支持 `mirrors` 数组，后续可挂自建 CDN。

### 测试通道：在 GitHub 上真机验证，又不想让普通用户拿到

默认只有 `stable` 通道。测试版本走一个**固定的滚动 tag `test`**，发布时标成 pre-release —— `releases/latest` 永远选不到它，所以普通用户的检查结果不会变成测试版；清单本身还带 `channel` 字段，通道不符的实例直接拒绝这份清单。

| | 正式通道 `stable` | 测试通道 `test` |
|---|---|---|
| 清单地址 | `releases/latest/download/update.json` | `releases/download/test/update.json` |
| 安装包地址 | `releases/latest/download/<文件名>` | `releases/download/test/<文件名>` |
| 镜像（jsDelivr） | 有 | 无（只认那一个滚动 tag） |
| 仓库根 `update.json` | 覆盖写入 | **不写**，避免污染镜像 |
| GitHub Release 类型 | 正式 | pre-release，可带 `expiresAt` |

出包并发布到测试通道：

```powershell
.\package.cmd -Bump patch -Channel test -ExpiresDays 7   # 清单带 channel=test，7 天后自动作废
.\scripts\release-github.ps1 -Channel test               # 只替换 tag test 的资产，不改 tag、不建正式 Release
```

本机切到测试通道（两种方式，环境变量优先）：

```powershell
$env:MIHOME_UPDATE_CHANNEL='test'                                        # 当前进程生效
'test' | Set-Content -NoNewline "$env:APPDATA\Feiyu\MiHome\update\channel.txt"   # 托盘/资源管理器启动也生效
```

回到正式通道就是删掉 `channel.txt`（或改回 `stable`）。切换后旧缓存自动作废，因为 `state.json` 里也记了通道；测试通道每次启动都会重新检查，不必等 24 小时。

测试版本的号段规则：测试包用正常 patch 递增（如 1.0.2），正式发版时用同一版本号覆盖；验证完请切回正式通道，否则这台机器以后只会收到测试包。

隔离边界（重要）：这是**分发隔离**，不是**机密**。公开仓库里的 pre-release 资产本身仍然可以被猜到 URL 的人下载，只是任何默认实例都不会去取；若要“别人彻底拿不到”，得把包放到私有仓库或私有对象存储（R2/OSS 私有桶 + 预签名 URL 写进 `mirrors`），应用侧无需带 token。

### 本地验证更新链路（不需要发 Release）

应用只认联调源（支持本地目录或 HTTP 基地址）：优先读环境变量 `MIHOME_UPDATE_SOURCE`，其次读 `%APPDATA%\Feiyu\MiHome\update\source.txt`。配了就不再请求 GitHub：

```powershell
.\scripts\test-update.ps1              # 装 1.0.0 基线 → 出下一版包 → 启动已装实例
.\scripts\test-update.ps1 -SkipInstall # 已装基线，只出包并启动
```

手动等价步骤：

1. 装基线：`publish\release\1.0.0\MiHome-Setup-1.0.0-win-x64.exe`
2. 出下一版：`.\package.cmd -Bump patch`（版本目录里会自动有 `update.json`）
3. 先退出便携实例（它会占单实例互斥体，把已安装版本顶回去）
4. `$env:MIHOME_UPDATE_SOURCE='I:\AICode\MiHomeWin\publish\release\1.0.1'`，再启动 `%LOCALAPPDATA%\Programs\MiHome\app\MiHome.exe`
5. 设置 → 关于 → 检查更新 → 立即更新

分步骤验证：

- 只测静默安装：直接跑 `MiHome-Setup-<新版本>-win-x64.exe --silent`，观察目录轮转 + 自动拉起新版本。
- 只测下载校验：把 `update.json` 的 `sha256` 改错，点更新应提示 SHA256 不匹配，旧版本原样保留。
- 只测检查：删掉本地目录里的安装包，只留 `update.json`，应显示“发现新版本”但点更新报下载失败。

## 8. 验收清单（发版前）

- [ ] `build.cmd` 编译 0 错误，单文件从 `publish\sc-win-x64\MiHome.exe` 启动
- [ ] `package.cmd` 输出 `Release <版本> -> publish\release\<版本>`
- [ ] 安装器 `--self-test-root` 隔离安装/卸载通过（`helper.txt` success=1）
- [ ] 安装包可正常显示安装界面、完成安装、从「完成」页启动应用
- [ ] 卸载可从「应用和功能」或 `MiHome.exe --uninstall` 完成，默认保留用户数据
- [ ] 安装包 `FileVersion` / `ProductVersion` = 目标版本
- [ ] 安装包图标与主程序图标一致
- [ ] `SHA256SUMS.txt` 覆盖目录内全部产物
- [ ] `update.json` 与安装包同版本、`sha256` 与 `SHA256SUMS.txt` 里的一致，且已随 Release 上传
- [ ] 「关于 → 检查更新」能拿到新版本并完成静默更新（旧版本关闭 → 目录轮转 → 新版本自动启动）
- [ ] 单文件功能回归：扫码登录/二维码、已登录态恢复、设备加载、面板开关、托盘/关闭行为
